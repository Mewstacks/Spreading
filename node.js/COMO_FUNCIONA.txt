COMO FUNCIONA
=============

Servidor Node.js que envia mensagens e mídias pelo WhatsApp via HTTP.

SEGURANÇA
---------
- Toda rota de sessão exige Bearer JWT Ed25519 com tenant, sessão, ação e expiração
- O serviço guarda somente chaves públicas em WA_CAPABILITY_PUBLIC_KEYS_JSON
- Não existe API key simétrica global nem fallback de autenticação
- Helmet esconde informações do servidor nas respostas
- Rate limit: máximo 30 requisições por minuto por IP
- Número só aceita dígitos, sem injeção possível
- Tipos de arquivo são verificados numa lista fixa
- Erros internos nunca são mostrados para quem faz a requisição

ROTAS
-----
GET  /api/status           → Verifica uma sessão (ação `status`)
POST /api/enviar           → Envia texto/mídia (ação `send` + Idempotency-Key)
POST /api/sessoes/reset    → Gera novo QR (ação `reset`, uso único)
POST /api/sessoes/logout   → Despareia (ação `logout`, uso único)

VARIÁVEIS DO .env
-----------------
WA_CAPABILITY_PUBLIC_KEYS_JSON → mapa kid -> chave pública Ed25519 base64url
WA_CAPABILITY_ISSUER           → emissor esperado (`spreading-web`)
WA_CAPABILITY_AUDIENCE         → audience esperada (`spreading-wa`)
PORT                           → porta privada (padrão: 3000)

DOCKER
------
No Fly, o app não declara `services` nem `http_service`: só responde na rede
privada 6PN/.internal. As sessões LocalAuth persistem no volume.
